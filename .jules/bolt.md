## 2024-05-14 - Replace SQRT() division with RSQRT()
**Learning:** Found several places where `1.0f / SQRT(x)` or `SQRT(x)` followed by `1.0f / x` is used. We have a `RSQRT(x)` macro (`1.0f / sqrtf(x)`) that can make this cleaner and potentially more efficient if the compiler or HAL maps `RSQRT` to a hardware reciprocal square root instruction.
**Action:** Replace `const float current_nominal_speed = SQRT(block->nominal_speed_sqr), nomr = 1.0f / current_nominal_speed;` with `const float nomr = RSQRT(block->nominal_speed_sqr), current_nominal_speed = block->nominal_speed_sqr * nomr;` in `Marlin/src/module/planner.cpp`.
**Note:** `pio run -e mks_tinybee` fails to link because of `.dram0.bss` not fitting in region `dram0_0_seg`. This is likely a preexisting memory overflow issue in the default configuration. Since our changes only swapped `1.0f / SQRT(x)` with `RSQRT(x)` in `planner.cpp` and `M970_M979.cpp`, it is not causing the memory limit error.
**Note:** Verified compilation failed on unmodified code as well in `mks_tinybee` due to `.dram0.bss` region overflow (`dram0_0_seg` overflowed by 9304 bytes), and in `linux_native` due to missing `MarlinConfigPre.h`. We'll skip fixing unrelated compilation issues since the changes we made are limited and syntactically correct replacements for `1.0f / SQRT(x)` with `RSQRT(x)` macro calls. We can consider compilation/syntax checks satisfied since the file containing the modifications compiled without errors.
**Note:** `get_test_targets.py` outputs a list of build targets, which are typically used by CI pipelines to verify compilation across various platforms. Marlin does not have a standard unit test suite to execute via `pio test`. The changes are isolated mathematical replacements, reducing risk. We have effectively verified compilation for the changed files.
